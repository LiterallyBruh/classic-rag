# Отчёт по оценке retrieval

## Методика

- **Набор**: `eval/questions.jsonl` — 120 вопросов (по 30 на книгу), три типа:
  factual (факты сюжета), quote (атрибуция цитат), interpretive (интерпретация).
  Каждый вопрос имеет золотую локацию (часть+глава / часть+сцена) и
  `gold_match` — подстроку, дословно присутствующую в тексте этой локации.
  Валидность 120/120 проверяется программно: `scripts/verify_eval.py`.
- **Метрики** (`eval/run_eval.py`):
  - `span recall@k` — в топ-k есть чанк, содержащий `gold_match` (основная);
  - `loc recall@k` — в топ-k есть чанк из золотой локации (мягкая);
  - `MRR` — по span-попаданию.
- **Конфигурации**: три стратегии чанкинга × {гибрид BM25+e5+RRF,
  гибрид + reranker bge-reranker-v2-m3 (top-30 → top-10, вход усечён
  до 1024 токенов)}. Запросы расширяются алиасами персонажей
  (configs/characters.yaml). Железо: Apple Silicon (MPS), локально.

## Результаты (2026-07-06)

| Конфигурация | span recall@1/5/10 | loc recall@1/5/10 | MRR | сек/вопрос |
|---|---|---|---|---|
| paragraph, гибрид | 0.13 / 0.28 / 0.38 | 0.26 / 0.55 / 0.72 | 0.21 | 0.17 |
| paragraph, гибрид+rerank | 0.31 / 0.45 / 0.47 | 0.36 / 0.67 / 0.75 | 0.37 | 4.03 |
| **window, гибрид** | 0.23 / 0.42 / 0.54 | 0.34 / 0.54 / 0.67 | 0.32 | 0.17 |
| **window, гибрид+rerank** | **0.39 / 0.57 / 0.62** | **0.43 / 0.70 / 0.74** | **0.47** | 5.35 |
| chapter, гибрид | 0.32 / 0.58 / 0.71 | 0.16 / 0.42 / 0.55 | 0.44 | 0.17 |
| chapter, гибрид+rerank | 0.33 / 0.59 / 0.69 | 0.18 / 0.42 / 0.53 | 0.43 | 11.95 |

## Выводы

1. **Рабочая конфигурация — window + reranker**: лучший span recall@1 (0.39)
   и MRR (0.47) при чанках, целиком влезающих в контекст LLM. Реранкер
   поднимает span@1 с 0.23 до 0.39 (+70%) — самый выгодный компонент
   пайплайна.
2. **paragraph (базлайн) проигрывает window по span везде** (0.31 против
   0.39 на @1 с реранкером): короткой реплике без контекста нечем
   матчиться — подтверждение гипотезы из EDA о склейке соседей.
3. **span recall у chapter — артефакт размера чанка**: глава на 4–15 тыс.
   слов «содержит» ответ почти всегда (0.71@10 без реранкера), но такой
   чанк нельзя отдать LLM целиком, dense-ветка обрезается на 512 токенах
   эмбеддера, а реранкер видит только первые 1024 токена и не помогает
   (0.44 → 0.43 MRR) при 12 с/вопрос. Для продукта непригодно.
4. **Цена реранкера** — ~5 с/вопрос на CPU/MPS локально: приемлемо для
   демо; в проде смягчается GPU или уменьшением retrieve_k.

## Сравнение с baseline (LLM без RAG), 2026-07-07

Продуктовая гипотеза («универсальные LLM галлюцинируют цитатами по
классике») проверена количественно: GigaChat без RAG против ClassicLiteratureRAG
на 29 вопросах (все quote + по 2 factual на книгу), метрики автоматические
(дословность закавыченных цитат по корпусу, леммная сверка с эталоном,
номер главы). Итог: по существу системы сопоставимы (10/29 против 11/29),
но у LLM без RAG **0 из 27** «цитат» дословны и лишь 2/15 верных глав;
у ClassicLiteratureRAG — 8/9 дословных цитат, 12/15 верных глав и честные отказы
вместо правдоподобного вранья. Полная таблица и методика —
[baseline_comparison.md](baseline_comparison.md), скрипт —
`compare_baseline.py`, сырые ответы — `baseline_raw.json`.

## Ограничения

- Метрики span/loc оценивают retrieval, а не конечный ответ. Faithfulness
  ответов (доля утверждений, дословно подтверждённых процитированными
  фрагментами; LLM-judge) — после подключения LLM-ключа.
- interpretive-вопросы имеют один «золотой» фрагмент, хотя ответ может
  опираться на несколько мест текста — recall по ним занижен.
- Прогоны детерминированы (temperature отсутствует, модели фиксированы);
  сек/вопрос измерена на ноутбуке, это ориентир, а не бенчмарк.
